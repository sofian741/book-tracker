# تاجر

تطبيق Android عربي بسيط لإدارة شراء وبيع الكتب، لمستخدم واحد، دون اتصال أو تسجيل دخول أو تتبع. الإصدار **1.0.2**، ومعرّف التطبيق `com.sufyan.booktracker`.

ثلاث وجهات: الرئيسية، الكتب، الإعدادات. أضف كتابًا وحدد عدد أجزائه الكلي، ثم أدخل أرقام الأجزاء التي تملكها مثل `1, 3`، ويقبل الأرقام العربية أيضًا. تظهر الأرقام في الواجهة بالصيغة الإنجليزية. كل جزء له مخزون ودفعات شراء ومبيعات مستقلة؛ يمكن بيع الجزء وحده وإضافة الأجزاء الناقصة لاحقًا. يمكن تكرار رقم الجزء في الإدخال لتسجيل أكثر من نسخة منه مثل `1, 1, 3`.

## التشغيل والتطوير

المتطلبات: Node.js 22 أو أحدث، npm. لبناء Android: JDK 21، Android SDK Platform 35 وBuild Tools 35.0.0. الحد الأدنى Android 6 (API 23)، مع Android System WebView حديث يدعم `dialog` و`structuredClone` (Chromium 102 أو أحدث).

```sh
npm ci
npm run dev -- --port 3000
```

للمعاينة المحلية على المنفذ 3000 بعد بناء الإنتاج:

```sh
npm start
```

أو بخادم ملفات ثابت:

```sh
npm run build
npx serve www -l 3000
```

لا تستخدم `npx serve . -l 3000`؛ مجلد المشروع يحتوي ملفات المصدر واستيرادات حزم وCSS التي تحتاج Vite. افتح العنوان الذي يظهر في الطرفية. للتشغيل دون خادم التطوير يجب تقديم `www` بعد البناء.

```sh
npm test
npm run cap:sync
```

`www` هو مخرج الإنتاج، ويُولّد قبل مزامنة Android. لا حاجة لأي خدمات أو متغيرات سرية. الخط والأيقونات محلية بالكامل. نسخة المتصفح أداة تطوير بتخزين IndexedDB، وليست إثباتًا لاختبار SQLite على Android.

اختبارات واجهة نسخة الإنتاج:

```sh
npx playwright install --with-deps chromium
npm run test:ui
# أو لاستخدام Chromium موجود في البيئة:
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:ui
```

## بناء Android

```sh
npm ci
npm run cap:sync
cd android
./gradlew assembleDebug
```

على Windows استخدم `gradlew.bat`. عرّف `ANDROID_HOME` أو ضع `sdk.dir` في `android/local.properties` محليًا. الملف الناتج: `android/app/build/outputs/apk/debug/app-debug.apk`. لا توجد مفاتيح إنتاج داخل المشروع. نسخة Debug للتجربة فقط، وليست للنشر على Google Play.

للتنزيل من GitHub: بعد دفع الملفات إلى `main` افتح **Actions → Android Debug APK**، أو اختر **Run workflow**. عند نجاح المهمة افتح **Artifacts → daftar-al-kutub-1.0.0-debug** وفك الضغط ثم ثبّت APK. يتطلب التثبيت السماح بالمصدر الذي نزّلت منه الملف. سير العمل يشغّل اختبارات الحسابات والواجهة والبناء، ولا يشغّل محاكيًا.

## الحسابات والتخزين

- كل المبالغ أعداد صحيحة بالقروش، مع إدخال مبالغ صحيحة بالجنيه في الواجهة، مع الاحتفاظ بدقة الحساب الداخلية بالقروش. سعر الشراء والبيع للجزء الواحد؛ المصاريف للدفعة/العملية بالكامل. تُسجّل المبيعات على رقم الجزء المحدد.
- التوزيع FIFO حسب تاريخ الشراء، ثم ترتيب تسجيل الدفعات لكسر التعادل في نفس اليوم. توزّع القروش الزائدة على أوائل نسخ الدفعة.
- الكتب ودفعات الشراء والمبيعات منفصلة منطقيًا، وتحتفظ كل بيعة بتخصيصاتها وتكلفتها. إضافة دفعة، حتى بأثر رجعي، لا تغيّر ربح المبيعات المحفوظة. البيع الجديد يسحب من المتاح حتى تاريخ البيع.
- تصحيح بيع أو شراء قديم وحذف بيع يعيد تخصيص المبيعات حسب تاريخها وترتيب تسجيلها، مع توضيح أن الأرباح قد تتغير. يُمنع خفض دفعة عن عدد النسخ المباعة منها، والبيع قبل توفر نسخ في تاريخه.
- سعر البيع المقترح ليس إيرادًا. المخزون بتكلفته وليس ربحًا. الشحن الذي يدفعه العميل لا يدخل ضمن سعر الكتاب. مصاريف شحن البائع تخصم من الربح.
- SQLite على Android عبر `@capacitor-community/sqlite`، في بيانات التطبيق الخاصة. تحفظ حالة الدفتر كاملة في صف واحد داخل transaction، مع `synchronous=FULL`؛ لا تظهر رسالة النجاح قبل اكتمال الكتابة. يتغير عرض الواجهة بعد نجاح الحفظ فقط. لا يوجد localStorage.
- إصدار SQLite `1` ونسخة بيانات الدفتر `2`. تُرحّل بيانات النسخة `1` تلقائيًا إلى نموذج الأجزاء باعتبار كل كتاب قديم جزءًا واحدًا، مع الحفاظ على دفعات الشراء والمبيعات وتكاليفها. استيراد النسخ الاحتياطية القديمة مدعوم بالترحيل نفسه. حفظ اللقطة الكاملة مقصود لتقليل تعقيد العمليات الذرية في دفتر صغير؛ ليس لتجارة بملايين السجلات.
- تحقق الاسترجاع يشمل المبالغ والكميات والتواريخ والمعرفات والعلاقات وتكاليف وتداخلات التخصيصات والإجماليات. النسخة غير السليمة لا تصل إلى الكتابة. القيم القصوى محدودة لمنع تجاوز دقة JavaScript.

## النسخ الاحتياطي

من الإعدادات اختر **تصدير نسخة احتياطية**. على Android تفتح نافذة مشاركة لملف JSON؛ اختر تطبيق ملفات أو مكانًا خارج التطبيق. الملف المؤقت داخل التطبيق وحده ليس نسخة آمنة. تحقق من وجود النسخة في المكان المختار. في المتصفح يُنزَّل الملف مباشرة.

لاسترجاعها اختر ملف JSON من منتقي الملفات، وراجع تحذير استبدال كل الدفتر ثم أكّد. تُفحص النسخة كاملة قبل استبدال الحالة داخل transaction واحدة. لا يُحذف شيء إذا فشل التحقق أو الحفظ. النسخ غير مشفّرة؛ احتفظ بها بمكان تثق به. النسخ السحابي التلقائي لـAndroid معطّل. حذف التطبيق يحذف قاعدة البيانات؛ صدّر نسخة قبل الحذف أو تغيير الهاتف.

## التحقق والحدود

اختبارات `tests/model.test.js` تتحقق من أمثلة 170 جنيه و40 جنيه وFIFO، وفروق القروش والخسارة والتعديلات والحذف والفترات والملفات التالفة، ومخزون الأجزاء وبيع كل جزء وترحيل بيانات الإصدار السابق. اختبارات Playwright تتحقق من الإنتاج والتدفق الأساسي والاسترجاع والتنزيل والحفظ بعد إعادة التحميل والحقن والشاشة الصغيرة وعدم الحاجة للشبكة. fixtures لا تدخل بيانات المستخدم.

يلزم فحص القبول التالي على هاتف أو محاكي Android قبل الاعتماد على الإصدار لبيانات فعلية:

1. أضف كتابًا متعدد الأجزاء (مثل 6 أجزاء مع إدخال 1 و3 فقط)، وبع الجزء 3 وحده، ثم أضفه مرة أخرى وتأكد من تحديث حالة الاكتمال والمخزون.\n2. أضف كتابًا وبع نسخة، ثم أغلق التطبيق قسريًا وافتحه؛ أعد تشغيل الهاتف وتأكد من نفس المخزون والأرباح.
3. سجّل عدة دفعات ومبيعات، صدّر نسخة إلى خارج التطبيق، ثم صحّح بيانات واسترجع النسخة؛ قارن الإجماليات.
4. اختر ملفًا تالفًا وتأكد من بقاء البيانات. جرّب إلغاء منتقي الملفات والمشاركة وانخفاض مساحة التخزين.
5. شغّل وضع الطيران وأعد الفتح والتسجيل والتصدير. اختبر لوحة المفاتيح وتكبير خط النظام وشريط الحالة وزر الرجوع.

لا توجد ديون أو عملاء أو مرتجعات أو تسويات تلف أو مزامنة في النسخة الأولى. لا تُسجّل التصرف المجاني كبيع صفري. يمكن حذف كتاب ودفعاته بعد تأكيد فقط إذا لم تكن له مبيعات؛ تُصحح العمليات الأخرى دون حذف تاريخ الكتاب.

الخط Noto Sans Arabic مرخّص بـSIL OFL؛ الرخصة في `licenses/`. الأيقونات المتجهة أصلية داخل المشروع.


## إدخال وبيع أجزاء الكتب (1.0.4)

- لإضافة المخزون، اكتب رقم الجزء في خانة الإدخال واضغط Enter؛ يتكوّن مربع مستقل لكل رقم. تكرار إدخال الرقم يزيد عدد النسخ من الجزء نفسه.
- حدّد مربعًا أو أكثر ثم أدخل سعر المجموعة واضغط «تطبيق السعر على المحدد». السعر الأساسي اختياري إذا تم تحديد سعر لكل جزء، ويُستخدم كقيمة افتراضية للأجزاء التي لم تخصص لها سعرًا.
- لإزالة رقم أُدخل بالخطأ استخدم علامة × على مربعه.
- عند البيع تظهر الأجزاء المتاحة فقط. اضغط الجزء لاختياره، واستخدم + و− لتحديد عدد النسخ، أو «تحديد كل المتاح» لبيع المخزون كله في عملية واحدة.
- سعر البيع في العملية الواحدة يطبق على كل النسخ المختارة؛ اختلاف أسعار البيع يسجل في عمليتين منفصلتين.
