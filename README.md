# تاجر

تطبيق Android عربي لإدارة تجارة الكتب (شراء، مخزون، مبيعات، حجوزات)، لمستخدم واحد، دون اتصال أو تسجيل دخول أو تتبع. الإصدار **1.1.0**، ومعرّف التطبيق `com.sufyan.booktracker` (لم يتغير). كان اسمه «دفتر الكتب».

## الصفحات
- **الرئيسية**: ترحيب «أهلًا أ/ الاسم»، الإعدادات أعلى اليسار، مبيعات وأرباح محققة (حسب الفترة)، قيمة المخزون، قيمة المشتريات، عدد الكتب (مكتمل/غير مكتمل)، الأجزاء الناقصة، وعدد الحجوزات مع الربح المتوقع (منفصل عن المحقق).
- **الكتب**: بطاقات مع «معايا جزأين من 6» وحالة الاكتمال، بحث وفلترة، تفاصيل، تعديل، حذف.
- **النواقص**: كتب المخزون التي ينقصها جزء أو أكثر فقط. الكتاب يختفي منها فور اكتماله (تُحسب من المخزون وليست مخزنة). زر «إضافة» لاختيار الأجزاء الناقصة أو نسخة إضافية من جزء موجود.
- **المحجوزات**: «محجوز عند العملاء» و«محجوز من الموردين»، تفاصيل تشبه الفاتورة، تأكيد/إلغاء بنافذة تأكيد، وسجل بالحجوزات المنتهية.

## السلوك المهم
- الأرقام إنجليزية، والمبالغ الجديدة أعداد صحيحة بالجنيه. التخزين الداخلي بالقروش للحفاظ على السجلات القديمة، والعرض مقرّب لأقرب جنيه.
- توزيع الأسعار على الأجزاء: 100 على 3 = 34/33/33. تعديل جزء يعيد توزيع المتبقي على الأجزاء التلقائية، وتعديل كل الأجزاء يحدّث الإجمالي، وتعديل الإجمالي يعيد حساب التلقائي مع احترام اليدوي قدر الإمكان. «تفاصيل شراء/بيع إضافية» لا تظهر لكتاب من جزء واحد أو عند اختيار جزء واحد.
- الخانات التي فيها قيمة افتراضية تُحدَّد عند الضغط عليها فيستبدلها الرقم الجديد.
- زر الرجوع يعيد للرئيسية قبل الخروج؛ النوافذ التي فيها بيانات غير محفوظة تحذّر أولًا؛ الخروج من الرئيسية بضغطتين خلال ثانيتين. (يعتمد على history ولا يحتاج إضافة `@capacitor/app`.)
- الحجز لا يسجل بيعًا ولا شراءً ولا ربحًا. حجز العميل يحجز الكمية من «المتاح للبيع» فقط (المخزون الفعلي − المحجوز) فلا يُباع مرتين. حجز المورد لا يضيف مخزونًا. التأكيد ينشئ البيع/الشراء الفعلي مرة واحدة (FIFO يُحسب عند التأكيد)، والإلغاء يحرر الكميات دون أثر مالي.

## التشغيل والتطوير
المتطلبات: Node.js 22، npm. لبناء Android: JDK 21، Android SDK 35، Build Tools 35.0.0. الحد الأدنى Android 6 (API 23) مع WebView حديث (Chromium 102+).

```sh
npm ci
npm run dev -- --port 3000     # تطوير
npm start                       # بناء إنتاج ثم معاينة على 3000
npm test                        # اختبارات المنطق
npm run test:ui                 # اختبارات الواجهة (Playwright)
npm run cap:sync && cd android && ./gradlew assembleDebug
```
لا تقدّم مجلد المصدر مباشرة بخادم ملفات؛ استخدم `npm start` أو قدّم `www` بعد البناء. الخط والأيقونات محلية بالكامل.

## البيانات والترحيل
- SQLite على Android (`user_version=1`) ونسخة الدفتر `2`: **لم يتغير**. الترحيل إضافي فقط: يُضاف `reservations: []` تلقائيًا عند القراءة أو استيراد نسخة قديمة، وحقل اختياري `salePrices` لكل كتاب (سعر بيع كل جزء؛ الكتب القديمة تستعمل `suggested` كما هو)، و`settings.userName` لاسم المستخدم. لا يُعدَّل أو يُحذف أي سجل شراء أو بيع قديم.
- تنبيه: لو أعدت تثبيت إصدار أقدم من التطبيق على بيانات أنشأها 1.1.0 فسيتجاهل الحجوزات ويحذفها عند أول حفظ. حدّث ولا تُرجع.
- `tests/model.test.js` (القديم) يعمل دون تعديل مع الموديل الجديد.
- كل حفظ يكتب لقطة الدفتر كاملة في transaction واحدة، وكل تأكيد/إلغاء حجز يتم على نسخة مستنسخة ثم تُكتب مرة واحدة: إما البيع والمخزون معًا أو لا شيء.
- النسخ الاحتياطي يشمل الحجوزات والاسم. الاسترجاع يتحقق من الملف كاملًا قبل الاستبدال، والملف التالف لا يمس البيانات.

## الحسابات
FIFO بتاريخ الشراء ثم ترتيب التسجيل. مصاريف الدفعة تُوزَّع على نسخها بالقروش دون فقد. تعديل سعر بيع أو بيانات كتاب لا يغيّر تكلفة الشراء التاريخية. تصحيح دفعة شراء قديمة يعيد تخصيص التكلفة وقد يغيّر الأرباح السابقة (يُوضَّح في النافذة).

## فحص القبول على Android قبل استخدام بيانات فعلية
لم يُجرَّب SQLite والمشاركة ومنتقي الملفات وزر الرجوع ولوحة المفاتيح على جهاز حقيقي. نفّذ على هاتف أو محاكي:
1. اسم أول مرة، ثم أغلق التطبيق قسرًا وافتحه: لا يُسأل عن الاسم مجددًا.
2. أضف كتابًا من 6 أجزاء وعندك 1 و3، سجّل بيعًا جزئيًا، أضف الناقص من «النواقص»، وتأكد أن الكتاب اختفى من النواقص عند الاكتمال.
3. سجّل حجز عميل وحجز مورد، أغلق التطبيق قسرًا وأعد تشغيل الهاتف، وتأكد أن الحجوزات والمخزون كما هي. أكّد واحدًا وألغِ آخر وراجع الأرباح.
4. زر الرجوع: من تفاصيل كتاب، من نافذة فيها بيانات غير محفوظة، ومن الرئيسية (ضغطتان للخروج).
5. تصدير نسخة إلى خارج التطبيق، تعديل بيانات، ثم استرجاعها ومقارنة الإجماليات. جرّب ملفًا تالفًا.
6. لوحة المفاتيح مع نماذج طويلة (إضافة كتاب بعدة أجزاء) وتكبير خط النظام ووضع الطيران.
